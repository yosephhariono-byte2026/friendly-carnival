# Pilih model sesuai beratnya tugas

Model cepat untuk pekerjaan sehari-hari dan perbaikan kecil. Model penalaran terkuat untuk arsitektur, debugging sulit, refactor besar, atau beberapa sistem yang saling terhubung. Ganti dengan /model. Nama model berubah dari waktu ke waktu, jadi pikirkan dari jenis tugasnya.

> "Use a stronger reasoning model when you're dealing with things like architecture, difficult debugging, larger refactors"
